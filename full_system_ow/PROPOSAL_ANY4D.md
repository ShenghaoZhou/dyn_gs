# Proposal: Multi-View Any4D Integration with Known Poses & Metric Depth Prior

**Branch:** `feature/any4d-integration`  
**Status:** Updated Design Plan (Incorporating Multi-View, Known Camera Poses, and Native Depth Prior)

---

## 1. Executive Summary of Changes

Based on your specifications, the design is upgraded in three key dimensions:

1. **Multi-View Batching ($M$-View Window)** instead of pairwise Two-View:
   - Any4D's foundation model (`any4d_4v_combined.pth`) is pre-trained natively on **4-view batches**.
   - Rather than isolated $(I_0, I_t)$ pairs, Any4D operates on a sliding temporal multi-view window:
     $$\mathcal{W} = \{I_0, I_{t-2}, I_{t-1}, I_t\}$$
     (Anchor frame $I_0$ + adjacent temporal frames).
   - Joint spatio-temporal self-attention across all $M$ views enforces cycle-consistent 3D scene flow and eliminates drift.

2. **Native Any4D Metric Depth Prior (Replacing MapAnything)**:
   - Current `full_system_ow` loads monocular depth from `model_infer/depth_{idx:05d}.npy` (generated by MapAnything / external estimators), which often suffers from scale ambiguity and edge bleed.
   - Any4D directly outputs metric camera-frame depth:
     $$Z_t(u, v) = \mathbf{P}_{\text{cam}, t}[u, v, 2]$$
   - This replaces MapAnything depth across the entire pipeline:
     - Frame 0 Gaussian parameter initialization (`init_gs_from_tracker_points`).
     - 3D point back-projection for geometric tracking (`add_new_points_from_depth`).
     - Keyframe densification and scale alignment.

3. **Conditioning on Known Camera Extrinsics ($T_{WC}$) and Intrinsics ($K$)**:
   - In datasets like HOT3D and robotic manipulation setups, camera calibration is known:
     $$T_{WC} = T_{CW}^{-1} \in \mathrm{SE}(3), \quad K \in \mathbb{R}^{3 \times 3}$$
   - Any4D's input pipeline natively accepts:
     - `view["camera_poses"] = T_WC`
     - `view["intrinsics"] = K` (converted to unit ray directions)
     - `view["is_metric_scale"] = True`
   - By anchoring camera motion, the transformer's task is transformed from uncalibrated 4D estimation into a **metric Multi-View Stereo (MVS) + Dynamic Object Scene Flow** problem, dramatically boosting accuracy and eliminating scale drift.

## 3. Detailed Component Specification

### Component A: `any4d_multiview_engine.py` (New Module)
A persistent worker/service managing the sliding multi-view window:

1. **Initialization**:
   - Loads `any4d_4v_combined.pth` using Hydra configuration with task override:
     ```python
     overrides = [
         "machine=local",
         "model=any4d",
         "model.encoder.uses_torch_hub=false",
         "model/task=calibrated_sfm", # or mvs / posed_sfm
     ]
     ```
   - Pre-allocates reference view $I_0$, its binary object mask $M_0$, and reference camera pose $T_{WC, 0}$.

2. **Window Formation**:
   - For frame index $t$, builds an $M$-view batch (e.g. $M=4$):
     $$\text{Batch Views} = [I_0, I_{t-2}, I_{t-1}, I_t]$$
   - Each view dict is populated with:
     ```python
     view = {
         "img": normalized_img,               # (1, 3, H, W) DINOv2 norm
         "camera_poses": T_WC.unsqueeze(0),    # (1, 4, 4) Known camera-to-world
         "intrinsics": K.unsqueeze(0),        # (1, 3, 3) Known intrinsics
         "binary_mask": mask.unsqueeze(0),    # (1, H, W) bool
         "is_metric_scale": torch.ones(1, dtype=torch.bool),
     }
     ```

3. **Inference & Outputs**:
   - Calls `loss_of_one_batch_multi_view(views, model, None, device, use_amp=True)`.
   - Returns for view $t$:
     - **Metric Depth Map**: `depth_z = pred[f"pred{M}"]["pts3d_cam"][..., 2:3]` (resized to original frame resolution via bilinear interpolation).
     - **Object 3D Trajectory**: $\mathbf{P}_t = \mathbf{P}_0 + \Delta \mathbf{P}_t$ for all pixels where $M_0 = 1$.
     - **Object Rigid Pose ($T_{CO}^{\text{any4d}}$)**: Derived via SVD rotation/translation alignment between $\mathbf{P}_0[M_0]$ and $\mathbf{P}_t[M_0]$.

---

### Component B: Depth Prior Substitution in `full_system_ow`

In the existing data loading pipeline:
- **Before:**
  ```python
  # Loaded from disk (MapAnything output)
  depth = np.load(data_dir / "model_infer" / f"depth_{frame_idx:05d}.npy")
  ```
- **Proposed:**
  When `--use-any4d` is enabled:
  ```python
  # Dynamically generated by Any4D multi-view inference
  depth = any4d_engine.get_depth(frame_idx) # Metric camera depth
  ```
- **Benefits over MapAnything depth:**
  1. Multi-view consistency: Depth is constrained across multiple viewpoints and known baseline distances ($T_{WC}$), eliminating scale drift.
  2. No pre-computation required: Operates in-situ directly on raw images + known camera poses.
  3. Dynamic object separation: Directly aligns depth with 3D scene flow vectors, reducing boundary bleeding between the hand and the manipulated object.

---

### Component C: Multi-View Tracking & Relocalization in `BundleSdfGS`

1. **Robust Pose Prior**:
   - At each frame $t$, the multi-view Any4D engine supplies $T_{CO}^{\text{any4d}}$.
   - Used as the starting guess for Stage 1 Photometric Levenberg-Marquardt optimization:
     $$T_{\text{guess}} = T_{CO}^{\text{any4d}}$$
   - Prevents the constant-velocity extrapolation failures observed when object velocities jump.

2. **Geometric Point Tracking Resilience**:
   - In Stage 2, if 2D feature tracking drops (`n_inliers < min_pnp_inliers`, as in frames 1–9 of `clip-001853`), Any4D re-seeds the tracker using the dense 3D points $\mathbf{P}_t$ and their 2D projections.

```python
@dataclass
class GlobalConfig:
    # Any4D Multi-view settings
    use_any4d: bool = True
    any4d_checkpoint: str = "Any4D/checkpoints/any4d_4v_combined.pth"
    any4d_window_size: int = 4            # M=4 views per window
    any4d_use_known_poses: bool = True     # Condition on T_WC
    any4d_replace_depth: bool = True       # Replace MapAnything depth prior
```
